> 把“一个参数到底怎么算定义清楚”这件事，变成机器能检查的最小规则。

现在我们已经写了一页草案，说一个参数描述符大概长这样：

```yaml
parameter_descriptor:
  parameter_id: motion.axis.max_velocity
  owner: motion.axis
  scope: axis
  semantic_name: max_velocity
  semantic_path_template: axis.{axis}.motion.max_velocity

  value:
    type: float
    unit: controller_defined

  access:
    readable: true
    writable: true
    contexts:
      - hmi_diagnostics

  activation_timing: owner_defined
  persistence_policy: profile_snapshot
```

但现在它还是“说明文档”。contract slice 的意思是把它变成“受管控的参数定义格式”。

具体要做的就是这几件：

1. **规定一条参数定义必须有哪些字段**

比如最小必须有：

```text
parameter_id       这个参数定义自己的稳定 ID
owner              谁负责这个参数
scope              这个参数挂在哪类对象上，比如 axis / machine / channel
semantic_name      这个参数在 owner 范围内叫什么
value.type         值类型
access.readable    能不能读
access.writable    能不能写
```

可选但推荐：

```text
semantic_path_template
value.unit
access.contexts
activation_timing
persistence_policy
```

2. **规定这些字段的值不能随便写**

比如：

```yaml
owner: motion.axis
```

必须能在 owner 列表里找到。

```yaml
scope: axis
```

必须能在 object scope 列表里找到。

```yaml
value:
  type: float
```

`float` 必须来自受管控的 `access_value_type` 值集合。

```yaml
access:
  readable: true
```

`true/false` 也不是随便写字符串，要来自已有的 `access_capability` 值集合。

3. **检查 owner 和 scope 是否配得上**

不是任何 owner 都能用任何 scope。

合理：

```yaml
owner: motion.axis
scope: axis
```

不一定合理：

```yaml
owner: tool_management
scope: axis
```

因为 tooling 管的是 tool/edge，不应该声明 axis 参数。

所以要有机器检查：

```text
(owner, scope) 必须在允许列表里
```

4. **检查参数 ID 不要混入实例值**

`parameter_id` 应该表示“参数定义”，不是某个具体 X 轴实例。

合理：

```text
motion.axis.max_velocity
```

不合理：

```text
motion.axis.x.max_velocity
motion.axis.tool_10.max_velocity
```

因为 `x`、`tool_10` 是具体实例，不应该写进定义 ID。

5. **检查 semantic_path_template 的变量对不对**

比如：

```yaml
scope: axis
semantic_path_template: axis.{axis}.motion.max_velocity
```

这里 `{axis}` 是对的，因为 `axis` scope 允许 `{axis}` 这个变量。

不合理：

```yaml
scope: axis
semantic_path_template: axis.{channel}.motion.max_velocity
```

因为 axis 参数里突然用了 `{channel}`，这就是错的。

现在 checker 已经会查 access definition 和 validation case。

```text
parameter_descriptor.owner
parameter_descriptor.scope
parameter_descriptor.value.type
parameter_descriptor.value.unit
parameter_descriptor.access.readable
parameter_descriptor.access.writable
parameter_descriptor.access.contexts
parameter_descriptor.activation_timing
parameter_descriptor.persistence_policy
```

也就是说，写错参数定义时，工具能直接报错，而不是靠人眼看。

**这不是要实现参数系统，也不是要做完整运行时。它只是先把“参数定义文件怎么写、哪些字段合法、哪些组合非法”这件事固定下来。**

做完这个 slice 后，后面才好继续做：

```text
参数目录生成
HMI 参数浏览
导入导出
运行时绑定
PLC/NC 引用参数
```

否则后面都会基于一堆“看起来像参数定义”的文档，很容易漂。
