更准确是：

- WSL2 的 `ext4.vhdx` 是动态虚拟磁盘。
- 它会随着 Linux 里实际写入的新块增长。
- 底层确实会按较小的块/分配单元扩展，所以 Windows Explorer 里看起来可能是“一段一段涨”，但通常不是固定每次 +8G 或 +16G。

- 真正危险的是“峰值写入”：比如构建过程中临时生成了 12G，然后你删掉，Linux 内部空间回来了，但 Windows 外侧 VHDX 可能已经从 `64G` 涨到接近 `76G`，不会自动退回。

所以你可以把它理解成：

`下一次 VHDX 大小 ≈ 当前 64G + 本轮曾经写入过的新增峰值`

会有一些块分配/文件系统余量，但不是倍增式扩容。对于 MetaNC 集成，关键控制点就是不要让构建峰值乱涨，尤其避免全 Docker build、大量重复 build 目录、重复 generated/report 快照并存。
