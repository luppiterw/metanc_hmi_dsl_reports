你 tab 不出来是正常的：在 Codex CLI 里，`/opsx:propose` 不是当前注册的 slash command 名称。

我本地确认到你这里有两套东西：

1. 推荐用法：Codex Skills
   这个仓库有：
   - `.codex/skills/openspec-propose/SKILL.md`
   - `.codex/skills/openspec-apply-change/SKILL.md`
   - `.codex/skills/openspec-explore/SKILL.md`
   - `.codex/skills/openspec-archive-change/SKILL.md`

   所以在 Codex 里直接说就行，例如：

   ```text
   用 openspec-propose 创建一个 add-user-auth change，实现用户登录
   ```

   或：

   ```text
   给“参数值集绑定”建一个 OpenSpec proposal
   ```

   我会自动按对应 skill 跑 `openspec new change ...`、`openspec status ...`、`openspec instructions ...` 并生成 artifacts。

2. 旧 custom prompt 用法
   你全局目录里有：

   ```text
   ~/.codex/prompts/opsx-propose.md
   ~/.codex/prompts/opsx-apply.md
   ~/.codex/prompts/opsx-explore.md
   ~/.codex/prompts/opsx-archive.md
   ```

   Codex 官方手册里 custom prompt 的调用格式是：

   ```text
   /prompts:<文件名去掉.md>
   ```

   所以这里应该是：

   ```text
   /prompts:opsx-propose add-user-auth
   /prompts:opsx-apply add-user-auth
   /prompts:opsx-explore add-user-auth
   /prompts:opsx-archive add-user-auth
   ```

   不是：

   ```text
   /opsx:propose
   ```

   如果刚新增或改过 `~/.codex/prompts/*.md`，需要重启 Codex 或开新会话才会加载；并且 custom prompts 已经是 deprecated，官方建议迁到 skills。

简短结论：以后在 Codex 里优先直接自然语言触发 `openspec-propose`；如果非要 slash，就用 `/prompts:opsx-propose ...`，不是 `/opsx:propose`。
