2. **High: HMI WorkOffset writes lack mode/run-state rejection for AUTO running.**
   The WorkOffset spec says program execution owns current selection during execution and HMI writes for current selection, `G500`, or offset values must be rejected by upper-layer mode control ([INTERFACE-REGISTRY.md](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/work_offset/docs/spec/INTERFACE-REGISTRY.md:148)). Current server routing just forwards commands to the adapter ([command_router.cpp](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/hmi/server/src/application/command_router.cpp:92), [composite_machine_adapter.cpp](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/hmi/server/src/adapters/composite_machine_adapter.cpp:72), [runtime_extension_collection.cpp](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/hmi/server/src/adapters/runtime_extension_collection.cpp:69)); `apply_suppression` then accepts based only on revision/mode.
   Risk: an HMI G500/action can race AUTO execution ownership. Recommend a server-side mode policy gate for `wcs.commands.activate`, `set_offset`, `clear_offset`, and `apply_suppression`, rejecting at least AUTO/MDI running states with a distinct mode-policy code. Client-side disabled state can be added, but should not be the only guard.

3. **Medium: status line wording is ambiguous and partly misleading.**
   Online status renders `Suppression TODO none` or `Suppression TODO G500` ([derived_state.py](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/hmi/client/web_client/runtime_fragments/derived_state.py:171), [dashboard.py](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/hmi/client/qml_client/runtime_fragments/derived_state_blocks/dashboard.py:107)).
