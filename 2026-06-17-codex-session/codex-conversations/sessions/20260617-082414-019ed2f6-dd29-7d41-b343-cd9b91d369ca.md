- `Work Offset` footer 打开 `runtime_state.parameter_view = work_offset`
- 表格节点：`parameter_wcs_table`
- 数据源：`res://wcs.offset.table`

V1 不做这些：

- selected-row activation
- G505-G599 创建
- Details 页
- G500 suppression
- 工件测量 / touch-off / probe
- program-frame / total-coordinate 页面

**表格行设计**
每一行是 HMI facade row，不是 WorkOffset domain record。行字段：

```json
{
  "row_key": "wcs:g54",
  "target_ref": "g54",
  "g_code": "G54",
  "offset_x": 320.0,
  "offset_y": -140.0,
  "offset_z": 330.0,
  "offset_a": 12.0,
  "offset_c": 90.0,
  "component_axis_ids": {

    "offset_y": "axis-y"
  },
  "active": true,
  "editable": true,
  "revision": 1,
  "active_state_revision": 7,
  "snapshot_revision": 7
}
```

HMI 用法：

- `row_key`：UI selection / trace key
- `target_ref`：set-offset 写入目标
- `g_code`：操作员可见选择名
- `component_axis_ids[field]`：visible column 到 WorkOffset axis id 的映射
- `revision`：cell edit 的 stale guard
- `active_state_revision`：activate 的 stale guard
- `snapshot_revision`：只做刷新/状态显示，不做 cell write guard

**Active Row 行为**
表格 active 状态必须来自 `row.active`，不能从 `wcs.active` 或 `G54` 字符串反推。

HMI 表现：

- active row 有明确视觉标记
- Web/QML 行为一致
- active row 变化以后以后端刷新后的 `wcs.offset.table` 为准

**Cell Edit 行为**
X/Y/Z/A/C inline edit 只在以下条件都满足时允许提交：

- `row.editable === true`
- `row.component_axis_ids[field]` 存在
- 输入值是 finite number

提交 payload：

```json
{
  "g_code": "G54",
  "target_ref": "g54",
  "field": "offset_x",
  "axis_id": "axis-x",
  "value": 123.45,
  "expected_revision": 1
}
```

其中：

- `target_ref = row.target_ref`
- `axis_id = row.component_axis_ids[field]`
- `expected_revision = row.revision`
- `g_code` 保留为兼容 echo

缺少 axis mapping 时，HMI 不发命令，显示类似：

`Work offset axis is unavailable; refresh and retry`

**Activate 行为**
V1 保留固定按钮：

- `activate_g54`
- `activate_g55`

按钮可继续在 DSL 中写 `g_code`，但 Web/QML dispatch 时应尽量从当前表格找到对应 row，并补全 payload：

```json
{
  "g_code": "G55",
  "selector": "G55",
  "expected_revision": 7
}
```

其中 `expected_revision = row.active_state_revision`。

找不到 row 时允许走 legacy fallback，只发 `g_code`，但 real backend 下推荐最终都带 revision。

**Stale / Reject 行为**
HMI 不做 optimistic patch。也就是说：

- 命令 accepted 前不本地改 row
- 命令 rejected 后不伪造成功 row
- 后端 post-command poll / resource update 是权威刷新来源

WorkOffset stale codes 映射：

- `work_offset.revision_mismatch`
- `work_offset.active_revision_mismatch`
- `work_offset.expected_revision_required`
- fixture 兼容：`wcs_revision_mismatch`

HMI notice：

`Work offset table changed; refresh and retry`

如果有 revision details，可以显示：

`Work offset table changed; refresh and retry (current 8, expected 7)`

**Web/QML Parity**
Web 和 QML 必须保持同一行为：

- 同一 `wcs.offset.table` row 字段
- 同一 set-offset payload
- 同一 activate payload
- 同一 stale notice 文案
- 同一 no optimistic patch 规则
- 同一 alias sync：`wcs.offset.table == tooling.wcs.table`
