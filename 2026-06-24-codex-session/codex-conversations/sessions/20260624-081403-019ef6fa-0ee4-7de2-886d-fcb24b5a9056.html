`rt_gateway` 是 NRT 到 RT 的通讯聚合层。它应该拥有 `rt-sdk::Machine` 连接、连接状态、RT 状态缓存、命令转换和 ROS2 服务/Topic，不应该拥有参数目录或领域数据。

产品级规则应是：

- HMI、ProgramEngine、Parameters、Diagnostics 等 NRT 模块不直接用 `rt-sdk`。
- 它们通过 ROS2 service/topic 调 `rt_gateway`。
- `rt_gateway -> rt-sdk -> OPC UA -> RT RtApi`。
- RT 内部仍通过 RtApi/Backends 映射到 Core/Orocos，不暴露 MotionBank 等内部实现。

这和当前 repo 边界一致：`rt-sdk` 是 userland RT 通信边界，[rt-sdk README](/home/iaar/workspace/ccmix-wp/MetaNC/rt-sdk/README.md:1)；`rt-api-contract` 是 RT 与 rt-sdk 共享 wire contract，且 rt-sdk 不允许链接 RT Core/Orocos。[rt-api-contract README](/home/iaar/workspace/ccmix-wp/MetaNC/rt-api-contract/README.md:6)

**关键交互**

- HMI 读/改参数：`HMI -> Parameter Service -> Unified Access Registry -> owner dispatch`。如果是刀具表，分发到 Tooling；如果是零偏，分发到 WorkOffset；如果是 RT-bound motion/hal/runtime state，则通过 `rt_gateway` 读快照或申请 apply。
- 程序执行：`HMI -> ProgramEngine -> Parser -> NC Kernel -> Scheduler -> rt_gateway -> rt-sdk -> RT`。ProgramEngine 文档已经定义公共 seam 是 ROS2，[MODULE-MODEL.md](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/program_engine/docs/spec/MODULE-MODEL.md:95)，并接受 ROS2 services + lifecycle topic 的模型。[0013 decision](/home/iaar/workspace/ccmix-wp/MetaNC/nrt/program_engine/docs/spec/MODULE-MODEL.decision/0013-ros2-seam-transport-agnostic-core.md:31)
- 参数应用到 RT：`Parameter Service` 先做 owner/access/activation 校验，再经 `Execution Policy` 判断当前模式和运行状态，最后由 `rt_gateway` 调 RT SDK。RT 参数 API 需要进入 `rt-api-contract/RtApi`，否则只能停留在 NRT 配置或 deploy-time 配置。
- 诊断数据：`rt_gateway` 发布 RT 状态、执行状态、过程数据；`Parameter Service` 发布参数变更/audit；ProgramEngine 发布 session/lifecycle；Data & Diagnostics 汇总。
