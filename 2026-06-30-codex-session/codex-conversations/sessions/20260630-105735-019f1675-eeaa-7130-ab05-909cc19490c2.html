    -DCMAKE_TOOLCHAIN_FILE="${CMAKE_TOOLCHAIN_FILE}" \

Why this is the smallest safe change:

- Current explicit install creates `/workspace/metanc_hmi_dsl/server/vcpkg_installed`.
- CMake manifest mode currently defaults to `build/vcpkg_installed`, creating the duplicate dependency tree.
- Adding `-DVCPKG_INSTALLED_DIR=.../server/vcpkg_installed` makes CMake reuse the preinstalled tree instead of creating `build/vcpkg_installed`.
- Runtime packaging stays unchanged because the Dockerfile already copies runtime `.so` files from `server/vcpkg_installed` into `/workspace/hmi-runtime/lib`.

I would not delete the explicit `vcpkg install` as the first fix. That would also require changing the runtime library copy path to `build/vcpkg_installed`, and it would move dependency installation into the source-copy/build layer, hurting Docker cache behavior on normal server source edits.

Risks/tests:

- Risk: if vcpkg changes behavior around shared install roots, CMake may still run a manifest verification/install step, but it should not create the second tree.
- Risk: if a future Dockerfile changes the explicit vcpkg install root, the CMake arg must be kept in sync. A named `ARG VCPKG_INSTALLED_DIR=...` would be a slightly larger but cleaner variant.
- Test with `docker build --target build -f nrt/hmi/docker/hmi-server.Dockerfile nrt/hmi`.
- Inside the build image, verify only `/workspace/metanc_hmi_dsl/server/vcpkg_installed` exists and `/workspace/metanc_hmi_dsl/server/build/vcpkg_installed` does not.
