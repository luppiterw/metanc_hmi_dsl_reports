Codex Response 4 / final_answer

2026-06-12 11:23:37 +0800
看了一下官方文档，Notion CLI 叫 `ntn`。它能做的事大致分 6 类：

1. **登录和凭证管理**
   - `ntn login` / `ntn logout`
   - 支持浏览器登录、无浏览器登录、`NOTION_API_TOKEN` 用于 CI/脚本
   - `ntn doctor` 检查认证、keychain、网络、配置状态

2. **直接调用 Notion API**
   - `ntn api v1/users`
   - `ntn api v1/pages/<page-id>`
   - 支持 GET/POST/PATCH、inline JSON、stdin JSON、headers、query params
   - 可用 `ntn api ls` 查看可用 API endpoints
   - 可用 `--spec` / `--docs` 查某个 endpoint 的 schema 和官方文档

3. **页面 Markdown 操作**
   - `ntn pages get <page-id>`：把页面取成 Markdown
   - `ntn pages create`：从 Markdown 创建页面
   - `ntn pages update <page-id>`：用 Markdown 更新页面内容
   - `ntn pages trash <page-id>`：删除到回收站

4. **Data sources / 数据表操作**
   - `ntn datasources query <data-source-id>` 查询数据源
   - `ntn datasources resolve <database-id>` 从 database 解析 data source ID
   - 创建、更新 schema、模板列表等通常通过 `ntn api v1/data_sources...` 做

5. **文件上传**
   - `ntn files create < ./photo.png`
   - `ntn files create --external-url https://...`
   - `ntn files list`
   - `ntn files get <upload-id>`
   - 上传后还要再用 `ntn api` 把 upload ID 附加到页面、block、cover、icon 或 files 属性里

6. **Notion Workers**
   - `ntn workers new` 创建 TypeScript worker 项目
   - `ntn workers deploy` 部署到 Notion 托管环境
   - `ntn workers exec <key>` 本地或远程执行 capability
   - 支持 sync、agent tool、webhook、env secrets、OAuth、runs/logs、TUI 管理

我会把它定位成：**Notion 的官方终端入口 + API 调试器 + 自动化脚本工具 + Workers 部署工具**。如果是长期产品集成，核心运行逻辑还是更适合用 REST API/SDK；如果是本地脚本、CI 发布报告、导入导出、调试接口、部署 Notion Workers，`ntn` 很合适。

本机当前没装 `ntn`，但 Node `v24.14.1`、npm `11.11.0` 满足 Workers 文档里的 Node 22+/npm 10+ 要求。

参考的官方文档：
- https://developers.notion.com/cli/get-started/overview.md
- https://developers.notion.com/cli/reference/commands.md
- https://developers.notion.com/cli/guides/api-requests.md
- https://developers.notion.com/cli/guides/data-sources.md
- https://developers.notion.com/cli/guides/file-uploads.md
- https://developers.notion.com/workers/get-started/overview.md

能用。`ntn` 支持令牌方式，不一定要 `ntn login`。

用法是设置环境变量：

```bash
export NOTION_API_TOKEN=REDACTED_NOTION_API_TOKEN...
ntn api v1/users/me
```

或者只对单条命令生效：

```bash
NOTION_API_TOKEN=REDACTED_NOTION_API_TOKEN... ntn api v1/users/me
```

要点：

- `NOTION_API_TOKEN` 会优先于 `ntn login` 存在 keychain 里的凭证。
- 适合 CI、脚本、无人值守任务。
- 令牌权限仍然受 Notion connection / PAT 的授权范围限制。
- 页面、database、data source 必须显式分享给这个 connection，否则 API 看不到。
- 不要把 token 写进 repo；用 shell env、CI secret、`.env` 本地文件更合适。

可以先用这个验证：

```bash
NOTION_API_TOKEN=你的token ntn api v1/users/me
```

如果返回当前 bot/user 信息，就说明 token 方式可用。
