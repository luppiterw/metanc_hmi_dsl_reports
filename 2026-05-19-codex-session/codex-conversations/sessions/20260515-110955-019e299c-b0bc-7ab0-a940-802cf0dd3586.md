**目标契约**
- backend `shutdown()` 抛异常时，报告：
  - `error/backend-shutdown-failed`
  - `role=<logger|time|io_hal|nrt_bridge|motion>`
  - `backend=<runtime selected backend name>`
  - `phase=shutdown`
  - `detail=<exception text>`
- 任何一个 backend shutdown 失败后，仍继续尝试剩余 backend teardown。
- 最终状态仍应回到 `STOPPED`，避免对象停在 `SHUTTING_DOWN` 或半初始化状态。

**实现设计**
核心改 [framework.cpp](/home/iaar/workspace/mirror-ccmix-wp/MetaNC/rt/plc/src/framework.cpp)。

建议复用上一轮加的 `backend_lifecycle_failure_message()`，再加一个 PLC-local helper：

```cpp
template <typename ShutdownFn>
std::optional<std::string> shutdown_backend(
    std::string_view role,
    std::string_view backend,
    ShutdownFn shutdown);
```

行为：
- 正常：调用 `shutdown()`，返回 `nullopt`。
- `std::exception`：返回 `error/backend-shutdown-failed: role=... backend=... phase=shutdown detail=...`。
- unknown exception：返回 `detail=unknown exception`。
- helper 不直接 `throw`，避免第一个失败中断后续 teardown。

**shutdown 顺序**
保持现有 reverse teardown 顺序：

```text
motion -> nrt_bridge -> io_hal -> time -> logger
```

设计上用 `first_shutdown_failure` 保存第一个失败。每个 backend 都尝试 shutdown：

```cpp
std::optional<std::string> first_failure;

record(shutdown motion)
record(shutdown nrt)
record(shutdown io)
record(shutdown time)
record(shutdown logger)
```

`record()` 只在 `first_failure` 为空时保存返回的错误，但仍然继续执行后续 shutdown。这样结果稳定，测试也简单。

**logger 特殊处理**
这里有一个关键点：`logger.shutdown()` 本身也可能失败。

建议策略：
- 对 `motion/nrt/io/time` 的 shutdown 失败，如果 logger 尚未 shutdown，可以 `emit(error/backend-shutdown-failed, message)`。
- 对 `logger.shutdown()` 失败，不能依赖 logger 再记录自己失败，所以最终 thrown error 是 canonical carrier。
- 最终如果 `first_failure` 存在，完成状态清理后 `throw std::runtime_error(*first_failure)`。

也就是说：
- logger 可用时，尽量发诊断。
- thrown exception 始终是可靠载体。
- 不引入新的 diagnostics framework。

**boot rollback 也要覆盖**
SPEC-067 写的是 shutdown failure，INV-044 写的是 teardown attempts all backend teardown。这个不只影响正常 `Framework::shutdown()`，也影响 `boot()` 失败后的 rollback。

建议同步改两处：
- 正常 shutdown path。
- `boot()` catch rollback path。

但要保持边界：不改 Behavior API、不改 backend interface、不引入生产 backend。

**测试设计**
扩展 [story19_backend_lifecycle_diagnostics_tests.cpp](/home/iaar/workspace/mirror-ccmix-wp/MetaNC/rt/plc/tests/story19_backend_lifecycle_diagnostics_tests.cpp)。

1. `shutdown_failure_reports_backend_lifecycle_detail`

  - `error/backend-shutdown-failed`
  - `role=io_hal`
  - `backend=noop_io_hal` 或当前 runtime selected name

  if (d.behaviors.size() > 2) {
