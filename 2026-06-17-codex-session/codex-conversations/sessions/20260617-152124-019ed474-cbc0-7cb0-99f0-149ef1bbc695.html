**Findings**

1. **Problem:** `wcs.commands.refresh_offset_table` 在 Slice 4 中同时被定义为“要做”和“延期/以后做”。
   **Location:** `delivery_plan.md:353` “`WO-S4-SPEC-004A`: Work Offset Refresh”; `delivery_plan.md:451` “explicit `wcs.commands.refresh_offset_table`”; `contract.md:338` “A later explicit Refresh command should”; `2026-06-17-work-offset-slice4-client-table.md:7` “Add a lightweight `wcs.commands.refresh_offset_table` facade”.
   **Boundary or contract risk:** 这是正式计划和执行计划的契约冲突。当前 server adapter 也只路由 `activate` / `set_offset`，未路由 refresh：`work_offset_runtime_extension_adapter.cpp:247` “return path == kActivateCommand || path == kSetOffsetCommand”。如果不先修文档，执行 agent 可能在“延期项”里实现新 server facade，或反过来跳过 Slice 4 必需的 Refresh。
   **Fix:** 二选一：要么把 explicit refresh 正式提升为 Slice 4，在 `contract.md` Commands 中明确 request/response、只读语义、alias sync 边界，并从 Deferred 删除；要么保留 deferred，Slice 4 plan 改成使用现有 poll/bootstrap refresh，不新增 `wcs.commands.refresh_offset_table`。

2. **Problem:** Slice 4 plan 的 refresh server 代码片段把 `active_state_revision` 当成 `snapshot_revision` 返回。
   **Location:** `2026-06-17-work-offset-slice4-client-table.md:351` “`*known != snapshot.active_state_revision`”; `:358` “`snapshot_revision`, json::number(snapshot.active_state_revision)”。正式契约区分三种 revision：`contract.md:85-87` row `revision` / `active_state_revision` / `snapshot_revision`。
   **Boundary or contract risk:** 这会混淆 activation guard 和 table refresh metadata。客户端可能用 active-state revision 判断表是否 changed，或把 table snapshot revision 显示/传递错，破坏 V1 stale handling。
   **Fix:** refresh 的 `known_revision` 必须和 table `snapshot_revision` 比较；返回字段 `snapshot_revision` 必须来自 `query_work_offset_view(settable_table)` 的 snapshot revision。若需要 active state，也另加 `active_state_revision` 字段，不要复用名称。

3. **Problem:** `Activate Selected` 计划把 HMI `row_key` 直接放进 `selector`，但契约中的 `selector` 是 WorkOffset/G-code selector。
   **Location:** `contract.md:35-37` 定义 `row_key` 为 opaque HMI key、`g_code` 为 selector；`contract.md:72` “Submit row `selector` or `g_code`”; `2026-06-17...md:176` “`selector: state://runtime_state.selected_wcs_row_key`”; 默认值 `2026-06-17...md:157` “`selected_wcs_row_key: wcs:g54`”。server 解析后直接传给 WorkOffset：`work_offset_backend_adapter.cpp:405-407` “`command.selector = request.selector`”。
   **Boundary or contract risk:** 如果 Web/QML enrichment 没有介入，server 会收到 `wcs:g54` 这种 HMI selection key，而不是 `G54`，把 UI-local identity 泄漏到 WorkOffset selector 语义里。
   **Fix:** retained action 不应把 `row_key` 当 selector。计划应明确：selection state 只用于查找当前行；实际 command payload 发送 `selector`/`g_code` 和 `expected_revision`，来源分别为 row `g_code` 和 row `active_state_revision`。如果要 server 接受 `row_key`，必须在正式 contract 中新增并命名为 selection key，不要塞进 `selector`。

4. **Problem:** `contract.md` 对 accepted `activate` / `set_offset` response 的 metadata 描述高于当前 retained interface/server 契约。
